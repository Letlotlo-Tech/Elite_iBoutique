# Part 3 submission checklist

The supplied brief asks for JavaScript interactivity, SEO, a client-side validated form, an external service embed, Git/GitHub version control, frequent pushes, descriptive commit messages, and an updated README.

## Before submission
- [ ] Run the website locally and complete every item in `README.md` → Testing checklist.
- [ ] Accept the course's private GitHub repository invitation.
- [ ] Ensure the project is in the correct private repository and push the latest commits.
- [ ] Update the README changelog whenever further changes are made.
- [ ] Copy the GitHub repository URL into the LMS submission field and provide any additional documentation requested by the lecturer.

## Useful evidence to capture
The shown brief does not explicitly say that screenshots are compulsory, but these are useful evidence if the lecturer or LMS asks for them:
1. Home page in the browser.
2. Products page showing product cards.
3. Services page with an expanded service detail.
4. Enquiry form showing required-field validation and a successful prepared-email hand-off (use sample details, not real customer data).
5. Contact page showing the embedded map.
6. GitHub repository page and commit history showing descriptive commits.
7. Mobile layout or responsive navigation.

Do not claim the form sends automatically: it opens a prepared email and the visitor must press Send.
